Instalację konfiguruje jeden plik: `.env`, obok `compose.yaml`. **Żaden plik
Compose nie jest edytowany w żadnym ze wspieranych układów.**

Sąsiednie strony tłumaczą ustawienia w kolejności, w jakiej się je napotyka. Ta
jest referencją: wszystkie klucze w jednym miejscu, żeby dało się sprawdzić
wartość znalezioną w cudzym `.env`.

<Callout type="warn" title="Trzy klucze nie mają wartości domyślnej i bez nich stos nie wstanie">
`AJ_ADMIN_TOKEN`, `POSTGRES_PASSWORD` i `RUNNER_WORK_DIR`. Compose odmawia
startu, zamiast podstawić pusty łańcuch, i jest to zamierzone: token
administratora, który po cichu zrobiłby się pusty, zostawiłby zamknięte `/admin`
— a razem z nim jedyną drogę do ustawienia hasła administratora.
</Callout>

## Co działa i skąd

| Klucz | Domyślnie | |
|---|---|---|
| `COMPOSE_PROFILES` | `edge,app,data,runner` | które usługi działają. Zobacz [cztery układy](/pl/install); `external-runner` jest dodatkiem do każdego z nich |
| `TZ` | `Europe/Warsaw` | kotwiczy [pracę z harmonogramu](/pl/install/schedule) w czasie lokalnym |
| `REGISTRY` | `ghcr.io/algojudge` | skąd pobierane są obrazy |
| `SERVER_TAG` | `0` | **ruchomy major**, bez `v`. Zobacz [Aktualizacja](/pl/install/update) |
| `CLIENT_TAG` | `0` | |
| `RUNNER_TAG` | `0` | Runner **oraz** jego cztery obrazy `lang-*` |
| `EXTERNAL_RUNNER_TAG` | `0` | własna wersja i własne repozytorium, więc własny tag |
| `POSTGRES_TAG` | `18` | major przypięty celowo — 18 przeniósł katalog danych |
| `NGINX_TAG` | `1.30-alpine` | stabilna linia nginksa: parzysty numer pomocniczy oznacza linię stabilną, nieparzysty — mainline |

## Sieć

| Klucz | Domyślnie | |
|---|---|---|
| `HTTP_PORT` | `80` | co publikuje dołączony nginx |
| `HTTPS_PORT` | `443` | |
| `SERVER_PORT` | `8080` | publikowany wyłącznie na pętli zwrotnej |
| `CLIENT_PORT` | `8082` | publikowany wyłącznie na pętli zwrotnej |
| `API_BASE_URL` | `/` | adres Servera tak, jak sięga do niego **przeglądarka**. `/`, gdy jedno origin obsługuje obie połowy. Dwa origins muszą być **tą samą witryną** — jedna domena rejestrowalna, jeden schemat — inaczej nikt się nie zaloguje. Zobacz [Za własnym proxy](/pl/install/reverse-proxy) |
| `APP_BASE_URL` | puste | jego odbicie lustrzane: adres **aplikacji** tak, jak sięga do niej przeglądarka. Puste jest właściwe przy jednym origin. Przy dwóch pozostawienie go pustym kończy logowanie federacyjne na gołym `/activities`, rozwiniętym względem origin API |
| `TRUSTED_PROXY_NETWORKS` | `172.28.0.0/24` | czyjemu słowu wierzyć w sprawie adresu odwiedzającego. **Sieć**, nie adres; `none`, gdy Server stoi bez proxy |
| `EDGE_SUBNET` | `172.28.0.0/24` | sieć Compose, w której stoi dołączony nginx |

**`EDGE_SUBNET` i `TRUSTED_PROXY_NETWORKS` muszą się zgadzać.** Domyślna para
się zgadza. Zmiana jednego bez drugiego oznacza, że Server przestaje wierzyć
proxy stojącemu przed nim, i każdy odwiedzający jest zapisywany jako przychodzący
z tego proxy.

## Runner

| Klucz | Domyślnie | |
|---|---|---|
| `RUNNER_WORK_DIR` | **wymagane** | **bezwzględna ścieżka na hoście**, i to **należąca do uid 65532**: brakującą Compose tworzy jako root, a wtedy każde zlecenie zawodzi z `Permission denied (os error 13)`. Ścieżka, której demon nie potrafi otworzyć, staje się pustym katalogiem, a nie błędem |
| `RUNNER_NAME` | `runner-1` | to, co pokazuje panel Zarządzanie |
| `RUNNER_PROBLEM_TYPES` | `standard-io@1,output-only@1` | co ten Runner oferuje do oceny |
| `RUNNER_TAGS` | puste | pule. **Czytane wyłącznie przy pierwszej rejestracji**; nazwanie puli zabiera Runnera z kolejki ogólnej |
| `RUNNER_STOP_GRACE` | `30s` | ile Docker czeka, zanim zabije Runnera. **Nic nie daje**: Runner ignoruje `SIGTERM`, więc w tym czasie niczego nie kończy — każdą z tych sekund odczekują `down`, `stop` i `update.sh`. Czyste zatrzymanie zaczyna się od drenowania. Patrz [Aktualizacja i wycofanie](/pl/install/update) |
| `RUNNER_LOG` | `info` | staje się `RUST_LOG` |
| `DOCKER_GID` | `999` | grupa właściciela gniazda demona. `0` na Docker Desktop |
| `SERVER_URL` | `http://server:8080` | tylko dla Runnera na własnej maszynie; `/api/v1` jest dopisywane |

## Runner zewnętrzny

Czytaj tylko wtedy, gdy `external-runner` jest w `COMPOSE_PROFILES`. Zobacz
[Zewnętrzny sędzia](/pl/install/external-runner).

| Klucz | Domyślnie | |
|---|---|---|
| `EXTERNAL_JUDGE_USERNAME` | **wymagane z profilem** | konto w archiwum. Każde przekazane zgłoszenie idzie z niego i na nim zostaje |
| `EXTERNAL_JUDGE_PASSWORD` | **wymagane z profilem** | odmawia tego `preflight.sh`, a nie `compose.yaml`: Compose interpoluje cały plik, zanim zastosuje profile, więc oznaczenie tego klucza jako wymaganego zepsułoby każdy układ, który tej usługi nie uruchamia |
| `EXTERNAL_JUDGE` | `uva` | które archiwum. Jeden proces obsługuje jednego sędziego; drugi to druga usługa |
| `EXTERNAL_RUNNER_NAME` | `external-runner-1` | **nie** `RUNNER_NAME`. To drugi Runner, z własną tożsamością i własnym zatwierdzeniem |
| `EXTERNAL_PROBLEM_TYPES` | puste | puste deklaruje własny typ archiwum. Literówka daje tu ciszę, a nie błąd |
| `EXTERNAL_RUNNER_TAGS` | puste | pule, czytane wyłącznie przy pierwszej rejestracji |
| `EXTERNAL_RUNNER_LOG` | `info` | staje się `RUST_LOG` |

Pięciu jego ustawień czasowych celowo nie udostępniamy: sprawdzają się nawzajem
przy starcie, domyślne wartości obrazu spełniają wszystkie te warunki, a zmiana
w dobrej wierze — łagodniejsze odpytywanie cudzego archiwum — jest właśnie tą,
która to psuje.

## Czego nie ma w `.env`

Część ustawień jest wpisana w `compose.yaml`, bo instalacja nie ma powodu ich
zmieniać: środowisko, w jakim działa Server, domyślny identyfikator
przechowywania, miejsce podmontowania prekonfiguracji, własna ścieżka robocza
Runnera wewnątrz jego kontenera oraz cztery obrazy językowe, budowane z
`REGISTRY` i `RUNNER_TAG`.

Server czyta znacznie więcej niż powyższe klucze — całość jest na stronie
[Konfiguracja Servera](/pl/server/configuration). Ops ustawia to, czego wymaga
instalacja, a resztę zostawia na domyślnych wartościach Servera.
